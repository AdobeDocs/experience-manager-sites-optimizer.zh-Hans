# 规范审计

**Canonical**&#x200B;审核将审核您页面上的canonical链接。 规范链接是页面`<head>`中的`<link rel="canonical">`标记，它命名页面内容的首选URL。 审核会标记缺失、设置错误或指向页面本身以外的其他位置的规范链接。

## 为什么它很重要

通常可以在多个URL中访问相同的内容，例如，使用或不使用尾随斜杠、使用跟踪参数或使用不同的大写。 除非另有说明，否则搜索引擎会将每个URL视为单独的页面。 规范链接会告诉他们您更喜欢哪个URL；这有助于他们将重复项分组、将集客链接等排名信号组合到一个URL上，并在搜索结果中显示该URL。

一个错误的规范链接可能比没有链接更糟糕。 搜索引擎可以忽略他们无法信任的规范链接，例如没有URL的链接、置于`<head>`外部的链接，或者多个不同意的标记之一。 指向其他页面的规范链接会要求搜索引擎将该页面显示在您的页面位置，这样可能会使您的页面出现在搜索结果之外。

## 审核检查的内容

审计将检查三个方面的问题：

* **该页面是否有一个规范链接：**&#x200B;缺少该规范链接，或者该页面是否有多个。 多个指向不同URL的规范链接将单独报告，因为搜索引擎可能会忽略所有这些URL。
* **标记是否正确设置：**&#x200B;标记是否在`<head>`之外，是否没有`href`特性或空特性，或是否带有可能导致搜索引擎忽略它的特性，如`hreflang`、`media`或`type`。
* **URL是否正确：**&#x200B;规范URL是相对的，而不是绝对的；在路径或查询字符串中包含大写字母；使用与页面不同的协议（`http://`或`https://`）；或者指向与正在编辑的页面不同的页面。

## 如何比较规范URL

Preflight在预览页面上运行，其主机通常与生产网站不同。 为了避免标记每个预览页面，审核操作不会比较规范URL的主机与页面的主机。 当它检查规范链接是否指向页面本身时，它仅比较URL的路径，因此`https://www.example.com/products/shoes`与预览页面`/products/shoes`匹配。 路径中的结尾斜杠和字母大小写不计算为此检查的差异。

## 已知限制

* **不同的域：**&#x200B;指向其他站点的规范URL未被Preflight标记，因为预览主机始终与生产站点不同。 确认规范URL中的域就是您期望的域。
* **HTTP `Link`标头：**&#x200B;预检只检查规范标记，而不检查HTTP `Link`标头。 如果某个页面仅在标题中设置其规范URL，则会报告该页面缺少规范链接。

## 如何解决

当审核发现机会时，每个机会都会描述问题和建议的更改。 在大多数情况下，页面应该在`<head>`中正好有一个规范链接，该链接具有一个绝对URL，该绝对URL的小写路径指向页面本身。 如果页面有意将其他页面指向其规范版本（例如重复或打印机友好副本），您可以将其保持原样。 审计仍会报告此情况。 要了解如何查看和解决机会，请参阅[Preflight中的审核结果](../../audit-results.md)。
