# ASO文档代理 — 查看学习情况

从有关该代理自身公关的人类公关审核反馈中汲取持久的经验教训。 读取
此文件位于`pipeline.md`中步骤4 （研究+草稿）的开头，正在起草中
任何事情 — 重点是，审阅者一次的更正都不应该是
又在未来的车票上做了一次。

## 属于此处的内容

只有&#x200B;**可泛化**&#x200B;反馈 — 将来票证上将会重复出现的模式，关于
色调、结构、缺少部分、文件放置错误或内容准确性。 示例：

- “始终提及支持忽略/跳过的业务机会的‘已忽略’选项卡。”
- “除非票证或现有的同级页面确认了审核，否则请不要主张Ultimate层审核 — 请将其注释掉，并改为标记为打开的项目。”
- “新的商机操作页面需要一个TOC.md条目和商机类型登陆页面上的卡片网格条目，而不仅仅是页面本身。”

## 哪些内容不属于此处

仅应用于单个PR的一次性机械反馈：拼写错误、断开的链接、
缺少逗号，该特定PR中的文件路径错误。 直接在公共关系中修复这些问题 — 他们
不要对未来的草案进行概括，因此持久的加入将只是杂音。

## 条目格式

```markdown
## YYYY-MM-DD — SITES-XXXXX (PR #NN)

**Lesson:** [one or two sentences — the generalizable rule]

**Why:** [what the reviewer actually said, or the specific mistake it corrects]

**Applies to:** [which ticket types / pages this affects — "all opportunity how-to pages", "settings/setup pages", "everything", etc.]
```

顶部的最新条目。 如果后面的课程取代或缩小了之前的课程，请编辑
要注意的较早条目，而不是在文件中留下两个冲突的规则。

&#x200B;---

尚无条目 — 在人工请求首次更改时，此文件将获得其第一个条目
这位探员的公关。
